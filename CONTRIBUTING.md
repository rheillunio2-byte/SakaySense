Thank you for your interest in contributing to **SakaySense**! Contributions of all kinds are welcome, including bug reports, documentation improvements, design suggestions, and code enhancements.

## Before You Start

- Check existing issues before opening a new one.
- Keep changes focused and easy to review.
- Do not present sample routes or fare estimates as official information.
- Do not add personal or sensitive commuter information to example data.
- Clearly identify mock, illustrative, or unverified transport information.

## Ways to Contribute

- Report bugs or unexpected behavior.
- Suggest improvements to route discovery.
- Improve fare estimator usability.
- Enhance delay-report workflows.
- Improve responsive layouts and accessibility.
- Update documentation.
- Help prepare the project for verified local transport data.

## Development Setup

1. Fork the repository.
2. Clone your fork.
3. Open the project in Visual Studio Code.
4. Run `index.html` using Live Server or a modern browser.
5. Make and test your changes.

```bash
git clone https://github.com/rheillunio2-byte/SakaySense.git
cd SakaySense
```

## Branch Naming

Use clear branch names, such as:

- `feature/route-search`
- `feature/fare-estimator`
- `fix/mobile-navigation`
- `docs/readme-update`

## Commit Messages

Write short, descriptive commit messages.

Examples:

- `Add destination search interaction`
- `Improve fare estimator layout`
- `Fix mobile route form spacing`
- `Update project documentation`

## Pull Request Process

1. Create a branch for your changes.
2. Make your changes and test them.
3. Commit and push your branch.
4. Open a pull request with a clear description.
5. Explain what changed and how you tested it.
6. Include screenshots for significant interface changes when possible.

## Reporting Issues

When reporting a bug, include:

- A clear description of the issue.
- Steps to reproduce it.
- Expected behavior.
- Actual behavior.
- Browser and device information.
- Screenshots, if helpful.

## Important Data Guidelines

SakaySense is a commuter information prototype. Route availability, fares, and delay reports must be treated carefully.

- Verify transport information with reliable sources before describing it as official.
- Include the source and date when adding verified fare or route information.
- Avoid publishing unverified reports as confirmed incidents.
- Respect commuter privacy and do not expose personal details.

## Code Guidelines

- Use clear, readable HTML, CSS, and JavaScript.
- Keep styling in `styles.css` and behavior in `app.js` where practical.
- Use descriptive names for functions and variables.
- Preserve responsive behavior.
- Consider accessibility, keyboard navigation, and reduced-motion preferences.
- Test changes in a modern browser.

## Code of Conduct

Be respectful, constructive, and welcoming. Focus feedback on the work, not the person. Harassment, discrimination, and intentionally disruptive behavior are not acceptable.

## Thank You

Every improvement helps make SakaySense more useful, understandable, and accessible to commuters.
